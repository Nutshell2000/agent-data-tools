Branch `cloud/20261116-brand`. No release version bump, nothing pushed, deployed or published, no payments.

## 1. "Glyphcall" in the service-level fields of payment terms and service cards

What each field is, as read in the code:

- The `serviceName` of a tool's 402 resource (`buildPaywall` in src/index.ts, the MCP payment wrapper in src/mcp.ts,
  `discoveryResources` in src/lib/discovery-index.ts, the `/v1` fronts' `FrontMeta` in src/lib/voice-fronts-openapi.ts
  and src/lib/openai-chat.ts) is `listingName(e.summary)`: ONE string that is both the x402 "service name" and the
  tool's own listing name. The Bazaar matches the search phrase at the start of that name (CLAUDE.md "Listing names",
  1.47.8 and 1.69.0), so it is **left alone**. A tool's description (`listingDescription`) is left alone too.
  tests/glyphcall-brand-metadata.test.cjs holds that a tool's quote differs from before in `iconUrl` only (resource,
  `accepts` and the Bazaar extension compared whole).
- There is no service-wide name or description field in the x402 quote, `/.well-known/x402` or `/discovery/resources`.

Strings that changed (new constant `SERVICE_BRAND = "Glyphcall"` in src/lib/public-brand.ts; a code constant, so a
quote and its settlement always agree and `quoteFingerprint` needs nothing for it):

| Where | Before | After |
| --- | --- | --- |
| `/buy/<slug>` 402 resource `serviceName` (src/index.ts `buildPaywall`) | `Agent Data Tools` | `Glyphcall` |
| `/credits/usdc/1`, `/5`, `/20` 402 resource `serviceName` (src/lib/usdc-credits.ts `routes`) | `API credits, prepaid $5` | `Glyphcall API credits, $5` (26 characters for $20; the x402 limit is 32, so "prepaid" moved to the description and stays in the tags) |

## 3. Browser pages on workers.dev answer 301 to glyphcall.com

The rule in one sentence (the owner's wording of 16 Nov, narrowed from the first brief): **on a host listed in
`BROWSER_PAGES_MOVED_HOSTS`, a `GET` whose `Accept` header contains `text/html`, for a path that is not a tool path and
not under a never-moved prefix, that carries no payment or key header and would answer `200 text/html`, answers `301`
to the same path and query on `PUBLIC_SITE_ORIGIN`; nothing else is redirected.**

- `movedBrowserPageUrl()` in src/lib/public-site.ts holds the whole rule; one `app.use` in src/index.ts (right after the
  canonical middleware) applies it after the response is known. The 301 carries `Cache-Control: public, max-age=3600`
  and `Vary: Accept`.
- Its own variable, production only: `"BROWSER_PAGES_MOVED_HOSTS": "agent-data-tools.revmesh2074.workers.dev"` in
  wrangler.jsonc. `RETIRED_PUBLIC_HOSTS` is unchanged and the workers.dev host is still never listed there: that older
  rule moves EVERY 200 HTML answer of a GET, including a browser's free-trial result page on a tool path, so it is not
  safe for the paid origin. wrangler.staging.jsonc has neither variable.
- Tool paths: `PAID_PATHS` (every `ENDPOINTS` path and `/buy/<slug>`), whatever the Accept header.
- Never-moved prefixes (`NEVER_MOVED_PREFIXES`; the path itself and everything below it):
  `/mcp`, `/v1`, `/credits`, `/.well-known`, `/keys`, `/oauth`, `/discovery`, `/openapi.json`,
  `/openapi-marketplace.json`, `/llms.txt`, `/llms-full.txt`, `/robots.txt`, `/sitemap.xml`, `/store`, `/buy`, `/order`,
  `/order-debug`, `/p`, `/payee`, `/examples`, `/skills`, `/clients`, `/review`, `/status`, `/revenue`, `/metrics`,
  `/health`, `/find`.
- Never-moved request headers: `payment-signature`, `x-payment`, `authorization`, `x-api-key`.
- Also never moved, by the conditions themselves: HEAD, POST and every other method; any client without `text/html` in
  Accept (curl, SDKs, agents), which keeps the 200 page with its canonical tag naming glyphcall.com as before; every
  answer that is not 200 or not `text/html` (the 402 page a browser gets on a tool URL, JSON, images, the IndexNow key
  file, XML).
- What does move: `/`, `/agents`, `/docs`, `/tools`, `/tools/<slug>`, `/guides…`, the `…-api` product pages,
  `/compare…`, `/vat-number-check…`, `/company-register…`, `/e-invoice…`, `/de/…`, `/benchmarks`, `/about`,
  `/changelog`, `/terms`, `/privacy`, `/support`, and any later page outside the list above.
- Loops: `www.glyphcall.com` → apex (old rule), workers.dev → apex (new rule), the apex never redirects (both functions
  refuse a host that is the public site). Staging is another host name and is not listed.

Tests, tests/workers-dev-browser-pages.test.cjs (10 tests; two Workers from the same build, one with the variable and
one without it as "before"):

- 15 human pages: 200 HTML without the rule, 301 with path and query kept with it, and the same page on glyphcall.com
  answers 200 with a self canonical.
- 57 other requests on workers.dev compared with the Worker without the rule: same status, `Location`, content type,
  `PAYMENT-REQUIRED`, `WWW-Authenticate`, `Cache-Control` and body (clock values and ids blanked). The table holds the
  hard cases, 200 HTML answers to a browser's GET that stay: `/credits`, `/store`, `/payee`.
- A browser's `trial=1` call: a 200 `text/html` result page on workers.dev, no `Location`.
- **A PAID tool request on the workers.dev host is not redirected**, with a browser's `Accept: text/html`: a prepaid
  key (claimed at `/credits/claim?session_id=…` on workers.dev against a Stripe fixture, then sent as
  `Authorization: Bearer`, as `X-API-Key` and as `api_key=`; the balance drops) and an x402 payment against the fixture
  facilitator (200, `PAYMENT-RESPONSE`, the tool's JSON). No real payment anywhere.
- www → apex in one step, apex 200, staging host 200.
- The pure function: every method, Accept value, status, content type, header, setting and prefix.

Known side effect: the funnel's `page_view` stage is marked by an inner middleware before the 301 replaces the answer,
so a browser that starts on workers.dev counts one page view there and one on glyphcall.com (the retired-host rule
has done the same since 1.173.0).

Not checked, only assumed: that Googlebot and Bingbot send `text/html` in Accept (they did in published request
samples). A crawler that does not keeps the 200 page whose canonical tag names glyphcall.com, as before.

## 4. robots.txt and the sitemap

- `withPublicSitemap()` (src/lib/public-site.ts) at the `/robots.txt` route: on any host other than the public site,
  while `PUBLIC_SITE_ORIGIN` is set, the `Sitemap:` line names `https://glyphcall.com/sitemap.xml`. The allow and
  disallow rules and the Content-Signal line are untouched; glyphcall.com names its own sitemap; staging (no public
  site) names its own.
  Before on workers.dev: `Sitemap: https://agent-data-tools.revmesh2074.workers.dev/sitemap.xml`.
- `/sitemap.xml` on workers.dev: **left answering 200 as today** (it lists workers.dev addresses). The owner's rule
  says nothing but browser HTML pages is redirected, so it is on the never-moved list. Search engines are no longer
  pointed at it. `sitemapXml` and scripts/indexnow.mjs were not edited. If the owner wants it gone, the choice is a
  301 to the brand sitemap (one line in the never-moved list plus a branch in the middleware), after the
  search-plumbing branch is merged.

## 5. `com.glyphcall` MCP Registry entries: prepared, NOT published

- `scripts/build-registry-manifests.mjs` now also writes `registry-drafts/com.glyphcall/tools.json` (`/mcp/compact`),
  `company-check.json` (`/mcp/company-check`) and `voice.json` (`/mcp/voice`): names `com.glyphcall/tools`,
  `com.glyphcall/company-check`, `com.glyphcall/voice`; titles "Glyphcall: Tools (find, describe, run)",
  "Glyphcall: Company and VAT check", "Glyphcall: Speech to text and text to speech"; descriptions
  "Glyphcall: find, describe and run pay-per-call data tools: prices, chain, web, PDF.",
  "Glyphcall: EU VAT (VIES), Nordic and French company registers, LEI and OFAC sanctions checks." (the focused
  server's own registry line), "Glyphcall: transcribe audio and video with SRT/VTT subtitles, and text to speech as
  MP3."; remotes, `websiteUrl`, icon and the key hint all on `https://glyphcall.com`; `$schema`, `version` and
  `repository` taken from server.json. No tool counts, no `packages` (the npm client belongs to the existing entry).
- Like `registry/`, the folder is generated and git-ignored (`registry-drafts/` in .gitignore), so the version in the
  drafts is always the release's. Run `node scripts/build-registry-manifests.mjs` to see them.
- `.github/workflows/publish-mcp.yml` loops over `server.json registry/*.json`; that glob cannot reach
  `registry-drafts/com.glyphcall/*.json`. tests/glyphcall-registry-drafts.test.cjs fails if the loop changes, if any
  workflow names `registry-drafts`, or if a draft's keys differ from the manifest the registry already accepts for
  the same server.
- To publish (the owner's steps, none taken): prove control of glyphcall.com to the registry with its publisher tool,
  by DNS (a TXT record on glyphcall.com holding the public key the tool is given; `mcp-publisher login dns --domain
  glyphcall.com …`) or by HTTP (a key file under `https://glyphcall.com/.well-known/`, which would need a route in the
  Worker). Check the exact record with `mcp-publisher login --help`: the form is from the registry's documentation as
  remembered, not verified in this session. Then `node scripts/build-registry-manifests.mjs` and
  `./mcp-publisher publish registry-drafts/com.glyphcall/<file>.json` for each of the three. The registry requires the
  remote URLs of a `com.glyphcall/*` entry to be on glyphcall.com, which they are. The `io.github.Nutshell2000/…`
  entries stay published as they are.

## After merge and deploy: the owner / release train

1. Nothing to set by hand: `BROWSER_PAGES_MOVED_HOSTS` is a plain production variable in wrangler.jsonc. No secret, no
   binding, no dashboard step.
2. Unpaid checks after the deploy (GETs only):
   - `curl -sI -H "Accept: text/html" https://agent-data-tools.revmesh2074.workers.dev/docs` → 301, `Location:
     https://glyphcall.com/docs`.
   - `curl -s -o /dev/null -w "%{http_code}" https://agent-data-tools.revmesh2074.workers.dev/docs` → 200.
   - `curl -s -o /dev/null -w "%{http_code}" -H "Accept: text/html" -A "Mozilla/5.0"
     "https://agent-data-tools.revmesh2074.workers.dev/time?zone=UTC"` → 402, and the same for `/credits` → 200.
   - `curl -s https://agent-data-tools.revmesh2074.workers.dev/robots.txt` ends with the glyphcall.com sitemap.
   - the `PAYMENT-REQUIRED` header of any tool quote decodes to `resource.iconUrl` `https://glyphcall.com/logo.png`.
3. Bazaar: a listing takes new metadata (here the icon; for the packs also the name) at that listing's next
   settlement. Tool names and descriptions did not change, so no re-seeding is called for; the icon follows as buyers
   pay. Nothing was paid or seeded here.
4. Search Console: the change-of-address tool does not apply (workers.dev is not a property that moves as a whole,
   and its API paths stay). Keep the glyphcall.com property and its sitemap; the workers.dev pages drop out as the 301s
   are crawled.
5. Registry: only if the owner wants the `com.glyphcall` entries, the steps in section 5.
